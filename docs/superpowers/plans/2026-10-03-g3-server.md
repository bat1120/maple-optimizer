# G3 (2단계): FastAPI 서버 Implementation Plan

> 자동 반복 모드(goal 설정 C). 성공 기준: `GOALS.md` G3. 스펙 §9, §12.

## Rulings
- Ruling: 넥슨 오류 → HTTP: 캐릭터 없음 404, 넥슨 호출 한도 503(`NEXON_RATE_LIMIT`), 점검·데이터 준비 중 502(`NEXON_UNAVAILABLE`), 키 오류 500(`SERVER_CONFIG`). IP 제한은 429로 따로 둔다 — 사용자가 "내가 너무 많이 눌렀다"(429)와 "넥슨 쪽 문제"(5xx)를 구분할 수 있게 — 틀리면 상태 코드만 바뀐다.
- Ruling: 캐시 단위는 (닉네임 소문자, 날짜|current) → 번들 전체 JSON. current TTL 15분, 과거 날짜는 30일(넥슨 약관의 30일 갱신 의무) 후 삭제.
- Ruling: IP 제한은 프로세스 메모리 슬라이딩 윈도(기본 분당 30회). 단일 VM 배포 전제. 다중 워커가 되면 Redis로 바꾼다.
- Ruling: 지원하지 않는 직업·무기는 422(`UNSUPPORTED`) + "계산 제외" 사유.

## File Structure
- `server/__init__.py`, `server/app.py` (create_app, 라우트, 오류 매핑), `server/cache.py` (BundleCache), `server/ratelimit.py` (SlidingWindow), `server/schemas.py` (pydantic 입출력), `server/service.py` (엔진 호출: 요약, 세팅 순위, 매물 평가)
- `tests/test_server.py` (≥ 12), `tests/goals/test_g3.py`

## Interfaces
- `create_app(fetcher: Callable[[str, date | None], dict], db_path: str, *, rate_limit: int = 30, window: float = 60.0, clock=time.time) -> FastAPI`
  - `fetcher`는 `NexonClient.fetch_bundle`과 같은 시그니처. 실서버는 `server.app.default_app()`이 `.env` 키로 만든다.
- 엔드포인트
  - `GET /api/health` → `{"status": "ok"}`
  - `GET /api/character/{name}?date=YYYY-MM-DD` → 요약(직업, 레벨, 기준 날짜, 활성 세팅, 엔진/API 스탯공격력, 참고 전투력, 프리셋별 장비 목록, 계산 제외 옵션)
  - `GET /api/character/{name}/settings?boss_defense=300` → 프리셋 조합 순위(최대 27)
  - `POST /api/character/{name}/listings` → 매물 평가 순위
