# G7 (4단계): 예산 최적화 Implementation Plan

> 자동 반복 모드(goal 설정 C). 성공 기준: `GOALS.md` G7. 스펙 §8.

## Rulings
- Ruling: 후보 행동은 "부위 + 그 부위에 들어갈 새 아이템 + 비용"이다(매물 구매든 직작 결과든 같은 형태). 스타포스 +n의 스탯 증가량 표가 아직 없어(넥슨 API·조사 범위 밖) "강화 후 아이템"은 사용자가 결과 옵션으로 넣는다 — 숫자를 지어내지 않기 위해 — 틀리면 직작 후보 입력이 번거롭다.
- Ruling: 직작 비용은 호출자가 고른 위험 기준(평균 또는 p75, 기본 p75)으로 하나의 숫자로 넘긴다(스펙 §8).
- Ruling: 탐욕법 = 남은 후보 중 (적용 후 지수 / 현재 지수 − 1) ÷ 비용이 가장 큰 것을 적용하고, 적용된 상태에서 다시 평가. 같은 부위는 한 번만. 비용이 남은 예산을 넘는 후보는 건너뛴다.
- Ruling: 평가기는 스냅샷당 보정(calibrate)을 한 번만 하고 재사용한다(`Evaluator`).

## Interfaces
- `engine/stats/evaluate.py`: `Evaluator(snap, setting, boss, catalog)`, `.index(items: dict[str, Item]) -> float`, `.base_items() -> dict[str, Item]`
- `engine/optimize/budget.py`: `Action(slot, item, cost, label)`, `Plan(actions, spent, index, gain_pct)`, `greedy(evaluator, actions, budget) -> Plan`, `brute_force(evaluator, actions, budget) -> Plan`
