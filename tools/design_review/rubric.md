# 디자인 심사 채점표 (판사 공통)

메이플 장비 최적화(웹) 화면을 심사한다. 너는 이 디자인을 만들지 않았다 — 만든 사람의 의도를 변호하지 말고, 처음 보는 사람의 눈으로 판단한다.
점수는 관대하게 주지 않는다. 4점은 "고칠 게 거의 없고 실제 서비스로 내놓아도 자랑할 만하다", 5점은 "이 분야 최고 수준(츄츄지지·환산주스탯보다 낫다)"이다.

## 입력
- `manifest.json`: 화면별 스크린샷 파일과 기계 판정 결과(가로 스크롤, 넘침, 두 줄 버튼, 글자 대비, 작은 터치 영역, 글꼴)
- 스크린샷: `<화면>__<pc|mobile>__<light|dark>.png` (화면: home, summary, summary-tooltip, upgrade, calc, scouter, error)
- 디자인 규칙: `design.md` — 이 서비스가 따르기로 한 문법(레퍼런스 3곳의 공통 문법). 규칙을 어긴 것도 지적한다
- 캡처 특성: 전체 페이지를 한 장으로 찍으므로, 휴대폰 아래 탭 막대(화면 고정)가 페이지 중간에 겹쳐 보일 수 있다 — 실제 화면에서는 맨 아래에 고정된다. 이것은 지적하지 않는다
- 제품 목적: 일반 메이플 유저가 닉네임을 검색해 내 스펙을 보고, **무엇을 먼저 바꾸면 보스 딜이 가장 많이 오르는지(억당 효율)**를 찾는다

## 채점 항목 (각 1~5점, 반드시 근거: 어느 화면·기기·테마의 어느 요소)
| 키 | 항목 | 5점의 모습 |
|---|---|---|
| polish | 완성도·첫인상 ("기깔나는가") | 정돈된 정렬·간격·모서리·색, 어색한 빈칸이나 깨진 곳 없음, 돈 들인 서비스처럼 보임 |
| hierarchy | 시각 위계 | 화면마다 가장 중요한 것(검색창, 캐릭터 핵심 숫자, 업그레이드 1순위)이 한눈에 먼저 보임 |
| consistency | 일관성 | 같은 역할의 요소가 같은 모양(카드·칩·버튼·표·제목), design.md 규칙을 지킴 |
| maple_fit | 메이플다움 | 메이플 유저에게 익숙한 정보 사이트 문법, 게임 정보(장비창·툴팁·등급색·스타포스)가 자연스러움. 공식 사이트 흉내는 아님 |
| readability | 가독성·정보 밀도 | 숫자·표를 읽기 쉬움, 너무 빽빽하거나 너무 휑하지 않음, 글자 크기·대비 충분 |
| task_flow | 과업 효율 | 검색 → 업그레이드 1순위 확인까지 헤매지 않음, 다음 행동이 분명함 |
| mobile | 휴대폰 품질 | 375px에서 넘침·잘림·어색한 줄바꿈 없음, 누르기 쉬움 |
| dark | 다크 모드 품질 | 다크에서도 위계·대비·색 의미가 유지됨 |

## 지적(issues) 쓰는 법
- 각 지적: `severity`(must|should|nice), `screen`, `device`, `theme`(both 가능), `where`(요소를 사람이 찾을 수 있게), `problem`(무엇이 왜 문제인지), `fix`(구체적으로 어떻게 — CSS 값·배치·문구 수준)
- 막연한 말 금지("더 세련되게", "모던하게"). 고칠 사람이 바로 손댈 수 있어야 한다
- 숫자·데이터 값 자체(계산 결과)는 심사 대상이 아니다. 화면 표현만 본다
- 기계 판정 항목(대비·넘침 등)은 이미 따로 잡히므로, 그 외의 것을 찾는 데 집중한다

## 출력 (JSON 하나만, 다른 글 없이)
```json
{
  "judge": "<판사 이름>",
  "scores": { "polish": {"score": 3, "evidence": "..."}, "...": {} },
  "issues": [ {"severity": "must", "screen": "upgrade", "device": "pc", "theme": "both", "where": "...", "problem": "...", "fix": "..."} ],
  "best": "가장 잘된 점 한 줄",
  "verdict": "한 줄 총평"
}
```
지적은 중요한 순서로 최대 10개.
